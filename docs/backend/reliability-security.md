# 백엔드 안정성·인증 개선

기준은 `main`의 `941a01c`입니다. Figma 수정본을 받기 전까지 화면 디자인은 유지합니다. 프런트 제품 코드 변경은 비밀번호 변경 성공 후 현재 세션을 로그아웃하는 처리입니다.

## 구현한 동작

| 영역 | 동작 |
|---|---|
| 인증 | JWT 서명·클레임에 더해 실제 사용자와 `session_version`을 확인합니다. 비밀번호 변경은 버전 조건으로 갱신하고 모든 기기의 이전 토큰을 무효화합니다. 기존 버전 없는 토큰은 버전 0으로 해석합니다. |
| 비밀번호·외부 로그인 | 기존 해시 형식을 유지하며 비동기 scrypt를 사용합니다. 로그인 비밀번호는 최대 72자입니다. Naver 요청은 10초 제한입니다. |
| 인증 요청 제한 | 가입·로그인·Google·Naver 진입은 IP당 15분에 20회, 비밀번호 변경은 사용자당 15분에 5회입니다. 관련 환경 변수로 조정할 수 있습니다. |
| 작업 시작 | 기본 처리·실패 이미지 재시도·OCR 수정과 추가는 DB 트랜잭션에서 대기열에 넣습니다. API가 직접 작업을 실행하지 않습니다. 처리 API는 202와 `queued`를 반환합니다. OCR 응답의 기존 `reprocessing` 문구는 유지합니다. |
| 작업 소유권 | 점유마다 새로운 UUID 토큰을 발급합니다. 이미지·프로젝트·OCR·번역·스타일·정리 메타데이터 저장과 작업 종료는 현재 실행 토큰이 일치할 때만 허용합니다. 같은 `WORKER_ID`를 다시 써도 이전 토큰은 사용할 수 없습니다. |
| 재시도 | 작업 대상과 시작 상태를 저장합니다. 완료 이미지는 보존하고 미완료 이미지만 초기 상태로 돌립니다. 수정된 OCR은 다시 원본 OCR로 덮어쓰지 않습니다. 기존 대기·실행 작업도 대상 목록을 채운 뒤 복구합니다. 최대 시도 수를 초과하면 실패 처리합니다. |
| OCR 저장 | 기존 영역 삭제와 새 영역 삽입을 한 트랜잭션으로 처리합니다. 삽입 실패 시 기존 OCR과 연결된 번역이 복구됩니다. 추가 영역 ID는 대기열에 저장해 재시도 시 중복 영역을 만들지 않습니다. |
| 이미지 생성 | DB에서 원자적으로 점유하고 heartbeat를 보냅니다. 중단된 유료 호출은 자동 재시도하지 않습니다. 기존 예약 비용을 유지하며 늦게 도착한 사용량은 기록할 수 있지만 결과는 공개할 수 없습니다. 기능을 비활성화해도 정리 스케줄러가 만료된 실행 상태를 복구합니다. |
| 삭제 | 작업 시작과 동일한 사용자→프로젝트 잠금 순서를 사용합니다. 대기·실행 작업이 있으면 프로젝트·생성 프로젝트·계정 삭제 모두 409로 거절합니다. 예약 후 신규 작성은 DB에서도 차단합니다. |
| 삭제 재시도 | 원본·썸네일·전처리·정리·생성 참조·생성 결과·실패 시도 경로를 수집합니다. 파일과 연결 Auth 사용자를 삭제한 다음 앱 DB 행을 삭제합니다. 실패 시 목록을 남기고 30초부터 최대 5분까지 간격을 늘려 재시도합니다. 완료 목록도 보존해 늦게 업로드된 파일을 다시 지웁니다. |
| 파일 정리 | 작업·점유별 경로를 사용합니다. 현재 이미지가 참조하는 파일은 미사용 파일 정리에서 제외합니다. 최대 100개씩 정리하고 마지막 정리 시각으로 순환하므로 뒤쪽 파일도 처리합니다. |
| 업로드 | 실제 바이트 수·이미지 형식·해상도를 검증하고 실제 크기를 기록합니다. 동시에 검증하는 이미지는 최대 4개입니다. Storage 버킷을 비공개로 설정하고 업로드 크기 제한을 적용합니다. |
| 종료·readiness | HTTP와 모든 작업자·정리를 하나의 종료 제한 시간으로 기다립니다. 시간이 지나면 네트워크 요청과 자식 프로세스를 중단합니다. 유휴 OCR 자식도 정리합니다. 종료 중 readiness는 즉시 503입니다. 필수 스키마·RPC·비공개 버킷 설정이 없으면 서버 시작을 거절합니다. |

공개 API 경로와 응답 필드는 유지합니다. 점유 토큰, 내부 파일 정리 시각, 삭제 표시는 생성 작업 응답에 포함하지 않습니다. 새 내부 테이블은 RLS를 사용하며 새 내부 함수는 `service_role`만 실행할 수 있습니다.

## 중간 백업

`codex/backend-reliability-security-20261008` 브랜치에서 작업합니다. 인증, 종료 처리, DB 작업 보호 등 의미 있는 단위가 끝날 때 커밋하고 GitHub에 푸시합니다. 한 단위의 작업이 마지막 백업 후 20분을 넘으면 WIP 커밋으로 먼저 백업합니다. 구현 전 기준 코드도 같은 브랜치로 백업했습니다. `main`은 수정하거나 병합하지 않습니다.

## 적용 순서

새 DB 보호 규칙과 이전 작업자를 섞어서 실행하면 안 됩니다. 다음 순서로 적용합니다.

1. 새 처리 요청을 막고 이전 서버의 현지화·이미지 생성 작업을 끝내거나 종료합니다. 이전 서버 인스턴스가 모두 내려갔는지 확인합니다. 중단된 유료 호출은 새 서버에서 실패 처리하며 자동 재호출하지 않습니다.
2. 새 코드의 빌드와 마이그레이션을 실행합니다. 기존 마이그레이션 기록과 체크섬을 유지합니다.

   ```sh
   npm run build --prefix backend
   npm run db:migrate --prefix backend
   ```

   추가 마이그레이션:
   - `20261008010000_session_versions.sql`
   - `20261008020000_job_fencing.sql`
   - `20261008030000_durable_deletion.sql`

3. 새 서버에 기존 비밀 환경 값을 설정합니다. `JWT_SECRET`을 유지하면 비밀번호를 변경하지 않은 기존 세션은 계속 사용할 수 있습니다. `.env.example`의 인증 제한 변수를 확인합니다. `JOB_HEARTBEAT_INTERVAL_MS`는 `JOB_STALE_AFTER_MS`보다 작아야 합니다.
4. 새 서버를 시작합니다. 시작 시 비공개 버킷과 크기 제한을 설정합니다. 설정 권한이 없으면 시작에 실패하므로 Storage 설정 권한도 확인합니다.
5. `GET /api/v1/health/ready`의 200을 확인하고 요청을 다시 엽니다. `npm run db:check --prefix backend`도 필수 스키마와 버킷 설정을 확인합니다.

이 작업에서는 운영 DB에 마이그레이션을 적용하거나 운영 서비스를 배포하지 않았습니다. Figma 디자인 수정도 포함하지 않습니다.

## 장애·롤백

삭제 실패 시 `deletion_tasks`의 `paths`, `status`, `attempts`, `next_attempt_at`, `error`를 확인합니다. 삭제 목록을 먼저 지우거나 Storage 정리 전에 사용자·프로젝트 행을 수동으로 지우지 않습니다. 삭제를 예약한 계정은 일반 요청을 사용할 수 없으며 DELETE 재시도는 허용합니다. 새 서버의 정리 작업자가 있어야 자동 재시도가 진행됩니다.

완료된 삭제 목록과 미사용 파일 목록은 늦은 업로드를 처리하기 위해 보존합니다. 장기 운영에서는 이 내부 목록의 보관 기간·성장량을 별도로 관리해야 합니다. 파일 삭제 요청은 반복해도 같은 경로만 대상으로 합니다.

DB 변경은 추가 방식입니다. 문제 발생 시 새 요청을 닫고 새 서버를 종료한 뒤 수정한 서버를 올립니다. 이전 `main` 서버를 그대로 다시 올리면 새 DB의 작업 보호 규칙과 충돌하고 세션 버전도 검사하지 않으므로 안전한 롤백이 아닙니다. 롤백할 서버에도 작업 토큰 검증과 세션 버전 검증을 유지합니다. DB의 점유·삭제 기록은 복구를 위해 남깁니다.

## 검증 방법

```sh
npm run build --prefix backend
npm test --prefix backend
npm run test:db --prefix backend
npm run build --prefix frontend
npm run lint --prefix frontend
# 별도 터미널에서 npm run dev --prefix frontend -- --host 127.0.0.1
node frontend/scripts/check-password-session.mjs
node frontend/scripts/check-workflows.mjs
```

`test:db`는 Linux/WSL의 PostgreSQL 14 도구로 `/tmp`에 새 클러스터를 만들고 전체 마이그레이션과 동시성 검사를 실행한 뒤 삭제합니다. `DATABASE_URL`을 읽지 않습니다. 기본 도구 경로는 `/usr/lib/postgresql/14/bin`이며 다른 설치 경로는 `TEST_POSTGRES_BIN`으로 지정합니다. 일반 사용자 권한으로 실행합니다.

DB 검사는 동시 점유, 같은 작업자 ID의 새 점유 토큰, 이전 토큰 저장 거부, OCR 실패 롤백, 시도 수 제한, 수정 OCR 보존, 계정 삭제와 현지화·생성 시작의 경합, 삭제 목록 보존, 유료 호출 비용 기록, 이전 형식 작업 복구, 미사용 파일 정리 순환, 필수 RPC 누락, 실행 권한을 확인합니다.

브라우저 검사는 실제 React 화면과 저장·다운로드 흐름을 사용하며 API·OAuth·유료 호출은 테스트 응답으로 대체합니다. 비밀번호 성공/실패 시 세션 처리와 360·390·768·1280px의 작업실·에디터·결과·생성 화면을 확인합니다. 자동 저장 재시도로 오류 안내가 먼저 사라지는 경우도 검사 스크립트가 처리합니다. Windows NPU/Paddle 모델과 실제 외부 API·운영 Storage 장애는 이 환경에서 실행하지 않았습니다.
