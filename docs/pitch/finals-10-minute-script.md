# Glocalizer 본선 발표 대본 · 10분 목표

작성 2026-11-02. 아래 시간은 목표 배분이며 실제 발표자의 리허설 측정값이 아니다.
공통: 샘플은 샘플이라고, 녹화는 녹화라고 말한다. 측정되지 않은 성능 수치를 말하지 않는다.

## 0:00–0:40 · 예나 · 문제 제시

“안녕하세요. 이모티콘 작가의 해외용 버전 제작을 돕는 Glocalizer입니다. 작가가 해외에 작품을 선보이려면 번역뿐 아니라 원래 글자를 지우고, 새 문구를 배치하고, 결과가 규격에 맞는지 다시 확인해야 합니다. 저희는 이 과정을 연결하면서, 작가가 결과를 이해하고 판단할 수 있는 근거를 함께 보여주는 데 집중했습니다.”

화면: 서비스 랜딩. 검증되지 않은 사용자 수·절약률은 넣지 않는다.

## 0:40–1:20 · 예나 · 사용자 문제

“특히 일본어를 모르는 작가는 번역문이 의도와 맞는지 판단하기 어렵습니다. 또 글자가 길어지거나 배경이 복잡하면 번역이 맞아도 바로 쓸 수 없습니다. 그래서 결과 이미지 한 장을 만드는 것에서 끝내지 않고, 인식한 원문과 선택한 표현, 검사한 항목을 확인하는 흐름을 만들었습니다.”

인터뷰 인용은 작가에게 공개 내용·이름 표기를 확인한 경우에만 추가. 미확인 상태에서는 위 일반 문제 설명을 사용한다.

## 1:20–2:00 · 예나 · 해결 흐름

“흐름은 생성, 현지화, 출시 전 검토입니다. 오늘은 먼저 로그인 없는 샘플 체험을 보고, 실제 편집 화면에서 넘친 글자를 수정한 다음, 재검사 결과와 내보내기를 보여드리겠습니다. 샘플 체험은 미리 처리한 결과를 재생하며 실시간 AI 처리와 구분합니다.”

화면: 랜딩의 ‘3분 샘플 체험’ 버튼. 시연용 샘플 3세트 승인·배포가 끝난 후 진행한다.

## 2:00–2:50 · 예나 · Demo Lab

“이 화면은 회원가입 없이 체험할 수 있습니다. 단색 배경, 복잡한 배경, 긴 문구 중 하나를 고릅니다. 원문 탐지 단계에서 어떤 글자를 읽었는지 보고, 일본어 후보를 뜻과 말투를 함께 살펴 선택합니다. 다음으로 글자를 지우기 전과 후를 비교합니다.”

클릭: 샘플 선택 → 원문 탐지 → 번역 언어 JA → 후보 선택 → 배경 정리 → 검사 결과.
“여기의 QA도 저장된 샘플 검사 결과입니다. 검사하지 않은 항목은 측정 안 됨으로 표시합니다.”

## 2:50–4:10 · 소연 · 실제 편집과 FAIL → 자동 배치

화면 전환: 미리 로그인해 둔 실제 서비스 에디터 탭. Demo Lab에서 프로젝트를 자동으로 넘긴다고 설명하지 않는다.

“이제 실제 편집 화면입니다. 긴 번역문이 캡션 영역을 넘치는 사례를 준비했습니다. 검사 근거에서 넘친 영역과 측정값을 확인한 뒤 자동 배치를 적용하겠습니다. 자동 배치는 글자 크기와 줄바꿈을 조정하고, 작가는 최종 모습을 확인할 수 있습니다.”

클릭: 실제 FAIL 프로젝트 → 넘침 근거 → 자동 배치 → 최종 PNG 확인 → 저장·재검사.

사전 준비: 소연에게 실제 재현 프로젝트·자동 배치 버튼 위치·FAIL 전후 PNG·재검사 결과 요청. 해당 증거가 없으면 장면을 성공했다고 대본으로 대체하지 않는다.

## 4:10–5:00 · 래원 · QA Board

“검사 결과는 이미지별로 볼 수 있습니다. 규격과 배치처럼 규칙으로 판정한 항목과 AI의 의견은 구분합니다. 이전 FAIL이 수정 후 어떻게 바뀌었는지 이력과 근거를 확인합니다. PASS는 Glocalizer 자체 검사 통과를 뜻하며 OGQ 승인을 보장하지 않습니다.”

클릭: QA Board → 방금 재검사한 이미지 → Evidence → 이력 비교.
필수 증거: 동일 이미지의 수정 전후 실제 보고서, rulesetVersion, inspectedAt. 다른 이미지의 PASS를 이어 붙이지 않는다.

## 5:00–5:30 · 예나 또는 래원 · 내보내기

“확인한 결과는 PNG나 ZIP으로 내려받습니다. 지금 선택한 결과와 내려받은 파일이 같은지도 확인할 수 있습니다.”

클릭: 내보내기 → 다운로드된 PNG 열기. 리포트 포함 기능이 배포된 경우에만 ZIP 안 리포트도 보여준다.

## 5:30–6:40 · 윤재 · 검사 구조와 AI 사용

“최종 이미지는 브라우저에서 합성하기 때문에 서버가 정리본만 검사하면 실제 출력과 다를 수 있습니다. 그래서 최종 PNG를 서버로 보내 바이트를 직접 읽고 규격을 검사합니다. 글자 배치는 브라우저가 측정한 결과를 활용합니다. AI의 문화적 표현 검토는 사람의 검토를 돕는 의견이며 확정 판정으로 취급하지 않습니다.”

화면: 구조 설명 또는 실제 Evidence. 현재 배포된 규칙 기준만 설명한다.

## 6:40–7:40 · 래원 · 성과와 원자료

“성능과 완주율은 실제 기록에서 계산합니다. 샘플 체험과 팀 내부 테스트는 외부 사용자 지표에서 분리합니다. 표본 수와 측정 기간을 함께 보여주고, 아직 기록하지 못한 수치는 측정 안 됨으로 남깁니다.”

화면: 배포된 Proof. N·기간·p50·p95 값을 발표 당일 확인해서 발언한다. 원자료가 없으면 개선 목표와 수집 방식까지만 설명한다.

## 7:40–8:40 · 예나 · 사용자 피드백과 개선

“저희가 확인하고 싶은 것은 단순히 번역이 나왔는지가 아니라 작가가 결과를 이해하고 활용할 수 있는지입니다. 인터뷰에서는 의미와 말투를 판단할 수 있었는지, 어디서 막혔는지, 다운로드하지 않았다면 왜 그랬는지를 묻습니다. 이 피드백을 번역 설명과 편집 UX 개선에 연결하고 있습니다.”

공개 동의를 받은 직접 인용이 있으면 1개와 대응한 수정 1개만 소개한다. 없다면 이 문단을 그대로 사용한다.

## 8:40–9:30 · 예나 · 권리·한계·다음 단계

“샘플에는 출처와 사용 근거, 폰트 라이선스, AI 생성 여부를 기록합니다. AI 번역과 의견은 오류가 있을 수 있으며, 자체 검사 통과가 스토어 승인이나 법적 안전을 뜻하지는 않습니다. 앞으로는 실제 작가의 완주와 재사용 사례를 더 쌓고, 실패가 잦은 배경과 문구부터 개선하겠습니다.”

화면: Source & Rights 체크리스트. 승인되지 않은 작품을 시연에 넣지 않는다.

## 9:30–10:00 · 예나 · 마무리

“Glocalizer는 작가가 해외용 버전을 만들고, 무엇이 달라졌고 무엇을 검증했는지 확인하도록 돕습니다. 번역 결과를 믿으라고 요구하기보다 작가가 판단할 수 있는 근거를 보여드리겠습니다. 감사합니다.”

## 장애 시 전환 멘트와 동일한 녹화 순서

“현재 네트워크 연결이 원활하지 않아, 같은 순서로 미리 녹화한 시연을 보여드리겠습니다. 지금 보시는 화면은 녹화본입니다.”

녹화 순서: Demo Lab → 실제 에디터 FAIL → 자동 배치 → 재검사 → QA Board 근거·이력 → 내보내기 → 실제 다운로드 PNG 확인.
녹화 화면에 ‘사전 녹화’와 촬영 날짜를 표시한다. 개발 fixture 영상은 ‘개발용 예시’로 표시하고 본선 실제 서비스 백업으로 사용하지 않는다.
