# 예상 질문과 리허설

## 질문·답변

- PASS는 OGQ 승인을 뜻하나요?
  “아닙니다. 해당 규칙 버전으로 Glocalizer가 확인한 항목의 통과이며, 스토어 심사는 별도입니다.”
- 측정하지 않은 항목도 PASS로 나오나요?
  “아닙니다. 해당 결과의 검사 기록이 없으면 측정 안 됨으로 구분합니다.”
- AI가 위험하다고 하면 사용할 수 없나요?
  “AI 의견은 확인 필요 수준의 제안입니다. 규칙 기반 FAIL과 구분하며 작가가 최종 검토합니다.”
- 왜 샘플을 미리 처리했나요?
  “로그인 없이 비용과 대기 없이 흐름을 체험하도록 했습니다. 실시간 처리와 구분해 모든 단계에 샘플 표시를 합니다.”
- 처리 시간과 완주율의 출처는 무엇인가요?
  “이벤트 원자료입니다. 표본 수와 측정 기간을 함께 제시하고 내부·샘플 이벤트를 실사용에서 제외합니다.”
- 이미지 저작권은 어떻게 확인했나요?
  “팀 생성 결과 또는 서면 허락 작품만 공개 샘플에 등록하고, 사용 근거와 폰트 라이선스를 기록합니다.” 실제 등록이 끝나기 전에는 ‘현재 확인 중’이라고 답한다.
- 번역이 맞는지는 어떻게 아나요?
  “뜻·말투 설명과 후보 비교를 제공하지만 AI 설명도 오류가 가능합니다. 중요 표현은 원어민 검토가 필요합니다.”
- 일반 번역기와 차이는 무엇인가요?
  “이미지 속 글자 인식, 배경 정리, 번역 문구 배치, 최종 이미지 검사와 내보내기를 하나의 작업 흐름으로 연결합니다.”
- 단계별 Replay 시간은 실제 값인가요?
  “저장된 실제 단계 이벤트만 표시합니다. 기록이 없는 단계에는 시간을 추정해 넣지 않습니다.”

## 팀원 장면 요청문 (초안, 전송 전)

소연: 동일 이미지에서 긴 문구 FAIL → 자동 배치 → 재검사하는 실제 프로젝트와 수정 전후 PNG를 부탁해. 발표에서는 2:50–4:10 구간이야.
래원: 같은 프로젝트의 QA 근거·이력, 최종 내보내기, 공개 가능한 Proof N·기간·원자료를 부탁해. 4:10–5:30 및 6:40–7:40 구간이야.
윤재: Replay 이벤트 필드와 샘플 처리 기록, 페르소나 비교 예시 3개, 배포된 QA 규칙 버전을 부탁해. 구조 설명은 5:30–6:40 구간이야.

## 리허설 기록지

발표자 실제 리허설 2회가 필요하다. 자동 UI 테스트 시간은 발표 리허설로 세지 않는다.

- 1회차: 미실시. 날짜 / 발표자 / 시작·종료 / 총시간 / 라이브 데모 시간 / 초과 구간 / 수정 사항 기록.
- 2회차: 미실시. 동일 항목 기록. 1회차 수정 사항 반영 여부 확인.
- 10분 초과 시: 기능 설명부터 줄이고 FAIL → 수정 → PASS와 결과 파일 확인은 유지.
- 장애 훈련: 네트워크 중단 시 녹화 전환 멘트 후 동일 순서로 재생.
- 발표 당일: 로그인 상태, 샘플 3세트, 실제 FAIL 프로젝트, 다운로드 경로, 녹화 파일 오프라인 재생, 화면 확대 100%, 알림 숨김 확인.
